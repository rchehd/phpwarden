## Rationale

The existing inventory lists Semgrep and EventHorizon as disabled by default. The user explicitly enables both in the Drupal profile, while the other five opt-in defaults remain unchanged; both default claims cannot be true.

## Proposed node

Checker IDs: composer-validate, composer-audit, dead-code, debug, syntax, yaml, whitespace, drupal-config, eslint, eventhorizon, gitleaks, stylelint, jscpd, phpcs, phpmd, phpstan, composer-require-checker, composer-unused, deptrac, rector, semgrep, twig-cs-fixer.

Off by default: composer-require-checker, composer-unused, dead-code, deptrac, rector. composer-audit is the only checker using the network (in a separate container seeing only copies of composer.json and composer.lock) and is optional by default; set `required: true` in CI. jscpd, phpmd and dead-code findings are warnings and do not fail the check unless `fail_on: warning`. eslint, stylelint and deptrac skip without a project config and never invent rules.

PHPStan needs `composer install` and a `drupal/core` matching `composer.lock`; otherwise it is reported unavailable while the other checkers still run. composer-require-checker and composer-unused need `--mode full`.

The Drupal profile enables Semgrep and EventHorizon by default. Semgrep uses bundled security rules without requiring a project rule file. EventHorizon checks Drupal caching and configuration with advisory findings (`fail_on: never`) but remains required, so failure to execute makes analysis incomplete and unsuccessful. Explicit `enabled: false` in a project file overrides these defaults.

Deptrac requires project architecture rules. Rector is chiefly for modernization and upgrades, always runs as dry-run, and needs project configuration or explicit targets/rules. The Composer package analyzers require installed dependencies and a supported package layout as well as full mode.
